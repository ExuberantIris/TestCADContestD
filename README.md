# ICCAD 2026 CAD Contest — Problem D: Timing Fixing by Useful Skew

`sa_solver` reads a clock-tree design and fixes setup/hold timing violations using only buffer
**resize** and buffer **insertion**, writing a legal `modified_clk_tree.structure` within the
contest's 600-second-per-testcase budget. This README covers *what is in this package* and *how to build/run it*.
This README was written with the help of AI agent.

## 2. Source files

| File | Role |
|---|---|
| `src/main.cpp` | Pipeline orchestration: time-budget bookkeeping, Phase 0→3 sequencing, dual-seed Greedy, final legality gate + fallback |
| `src/pd_parser.c` | Loads `buf.lib` / `clk_tree.structure` / `SS_delay.rpt` / `FF_delay.rpt` into a `PdDesign`, via O(1) hash-map name/path lookups |
| `src/pd_clock.c` | `pd_annotate_clock`: walks the tree accumulating SS/FF clock latency at every node |
| `src/pd_timing.c` | `pd_compute_timing`: per-path slack, WNS, TNS for both corners |
| `src/pd_mutate.c` | Tree edits: `pd_split_buffer`, `pd_insert_buffer_on_child`, `pd_remove_buffer`, and the synthetic zero-area "zero cell" (`pd_add_zero_cell` / `pd_cell_is_zero`) |
| `src/pd_checker.c` | `pd_check_legality`: final structural/naming/ancestor-order legality gate vs. the untouched original design |
| `src/pd_output.c` | `pd_write_structure`: writes `modified_clk_tree.structure` |
| `src/pd_util.c` | String/path helpers + `pd_is_new_buf_name` / `pd_find_node_by_name` |
| `src/lp_branch.cpp` | Builds the `LpBranch` model (one per parent→child edge) from the tree, incl. per-branch SS/FF delay bounds and the `allow_zero_cell` flag |
| `src/lp_mo_init.cpp` | Exact resize-only LP Init: tree difference-constraints, SPFA negative-cycle feasibility, bisection on the worst-case slack threshold (`tau`) |
| `src/insert_select.cpp` | Phase 0: `pd_find_branch_point` (walk up to the nearest true fork) + `insert_decoupling_buffers` |
| `src/lp_buffer_dp.cpp` | `LpBufferChainDp`: fanout/delay → minimum-area DP table, used only in Phase 0's insertion-cost estimate |
| `src/lp_eval.cpp` | Re-derives WNS/TNS/area/score from a continuous `(d_ss, d_ff)` vector without touching the real design; builds per-branch candidate delay lists |
| `src/greedy_postlp.cpp` | Phase 2: `greedy_post_lp` coordinate-descent hill-climber (commit/pass/attempt), incremental O(affected-paths) scoring, weighted-shuffle restarts |
| `src/apply_solution.cpp` | Phase 3: snaps the winning continuous solution to real library cells |
| `src/lp_score.cpp` | `lp_compute_score` (α=0.6/β=0.2/γ=0.2 formula) + `result.txt` writer |

`include/*.h` / `include/*.hpp` mirror this list 1:1 (one header per `.c`/`.cpp` module);
`include/pd_types.h` / `include/lp_types.hpp` hold the shared data structures
(`PdDesign`/`PdNode`/`PdCell`/`PdPath`, `LpProblem`/`LpBranch`/`LpSolution`), and
`include/pd_config.h` / `include/pd_c_api.hpp` hold compile-time limits and the C↔C++ bridge.

## 3. System requirements

- **OS**: Linux (the reference/dev environment is WSL2). The Makefile uses POSIX `sh`
  constructs, so a POSIX shell is required to use it as-is.
- **Compiler**: a C11 + C++17 toolchain (`gcc`/`g++`). The code uses C++17 standard-library
  features (e.g. `std::clamp`), so GCC ≥ 7 (or an equivalently current Clang) is recommended.
- **Build tool**: GNU Make.
- **No external libraries** — standard C/C++ only, no LP solver/BLAS/Boost. `-lm` is the only
  extra link flag.

## 4. Build

From the project root:

```bash
make build      # builds ./sa_solver
make clean      # removes all build artifacts (*.o, sa_solver, test_* binaries)
```

## 5. Run official testcase0–4

### 5.1 Direct invocation

```bash
./sa_solver <testcase_dir> [result_dir]
```

Example:

```bash
./sa_solver testcase/testcase0 result/testcase0
```

`<testcase_dir>` must contain `buf.lib`, `clk_tree.structure`, `SS_delay.rpt`, `FF_delay.rpt`.
This writes `result_dir/result.txt` (our own score report) and
`result_dir/modified_clk_tree.structure` (**the contest deliverable**).

### 5.2 Via the Makefile (build + run + report)

```bash
make build run TESTCASE=testcase0      # single testcase -> result/testcase0/
make TC=testcase1 run                  # TC is a short alias for TESTCASE
make run-all                           # build (if needed) + run testcase0..testcase4,
                                        # then regenerate result_summary.csv
make report                            # just re-scrape result/testcase{0..4}/result.txt
                                        # into result_summary.csv (no re-run)
```

## 6. Output files (per testcase, under `result/<testcase>/`)

| File | What it is |
|---|---|
| `modified_clk_tree.structure` | The contest deliverable. Only nodes reachable from root are written. |
| `result.txt` | Baseline / after-LP-init / after-optimize WNS, TNS, area, and score (α=0.6, β=0.2, γ=0.2). |

`result_summary.csv` (project root) aggregates the final score/area/WNS/TNS for
`testcase0`…`testcase4`, regenerated by `make report` / `make run-all`.
